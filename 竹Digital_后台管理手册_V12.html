🚑 网站404急救步骤 V12更正

⚠️ V11的急救步骤是错的！真正的404原因不是index.html消失，而是CNAME被删导致自定义域名失效。
  1. 第一步（最重要）：去 GitHub → 仓库 → Settings → Pages → Custom domain → 填入 zhudigital.com.au → 点 Save。GitHub会自动重建CNAME文件。
  2. 等2-3分钟，GitHub重新部署。
  3. 测试 zhudigital.com.au 是否恢复。
  4. 如果仍然404，再去 GitHub Actions 查看部署状态（绿色=成功，红色=失败）。
  5. 不要反复purge Cloudflare缓存——先确认Custom domain设置正确。
💡 根本原因：--force push 会删掉main里有而本地没有的文件（如CNAME）。CNAME消失 → Pages的Custom domain设置被清空 → 自定义域名失效 → 404。解决方法是恢复Custom domain设置，不是恢复index.html。

⚠️ 为什么push前必须先pull

GitHub Pages在你设置Custom domain时，会自动往main提交一个CNAME文件。如果你本地没有这个提交，直接push会被拒绝（non-fast-forward error）。如果强行--force push，CNAME就没了，网站立刻404。

# 正确做法：push前先pull
git pull origin main   # 把GitHub上的CNAME同步到本地
git push origin master:main   # 再push，安全

🔴 事故 #001：知识滚条不显示 + 网站404
发生时间：2026-10-25 深夜 ～ 2026-10-26 凌晨 | 修复：2026-11-13

现象：网站正文显示正常，但知识滚条（ticker）不出现。反复purge Cloudflare缓存无效。后来出现404。

Ticker不显示的原因：所有 git push 都推到了 master branch，但 GitHub Pages 实际部署的是 main branch。ticker代码永远没有到达生产环境。

404的真正原因 V12更正：执行了 git push origin master:main --force，force push 把 main branch 里的 CNAME 文件删除了（本地master里没有CNAME）。CNAME消失 → GitHub Pages的Custom domain设置被自动清空 → 自定义域名zhudigital.com.au失效 → 404。
（V11手册错误地说是"index.html被删"，这是不准确的——真正的元凶是CNAME。）

修复方法：在 GitHub → 仓库 → Settings → Pages → Custom domain 重新填入 zhudigital.com.au → Save。GitHub自动重建CNAME，Pages重新部署，网站恢复。

✅ 教训
  1. 永远不用 --force：会删掉GitHub有而本地没有的文件（CNAME！）
  2. push前先pull：git pull origin main 同步远程提交
  3. 404急救先看Custom domain：不是index.html，是CNAME/自定义域名设置
  4. Cloudflare不是万能药：purge缓存解决不了branch/CNAME问题
  5. 三思而后行：每个git命令执行前想清楚后果，特别是--force
